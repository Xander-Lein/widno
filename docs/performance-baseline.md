# Performance baseline

Измерения выполняются release-сборкой и скриптом
`scripts/benchmark-first-load.ps1`. Таймер начинается перед запросом
изображения и останавливается в следующем GUI-цикле после композиции
первого кадра. Пути с пробелами поддерживаются; для cold-load каждый файл
запускается отдельно.

Пример:

```powershell
.\scripts\benchmark-first-load.ps1 `
  -File "C:\path\to\image.jpg" `
  -Runs 5
```

## Зафиксированные результаты

На текущей Windows-системе, 3 запуска на файл:

| Источник | Median | Min | Max |
| --- | ---: | ---: | ---: |
| Большой JPEG `yande...jpg` | 1012 мс | 979 мс | 1081 мс |
| `_original_drawn...jpg` | 665 мс | 650 мс | 721 мс |
| PNG 3072×1296 | 63 мс | 61 мс | 64 мс |
| RAR fixture `фотки.rar` | 68 мс | 63 мс | 71 мс |

## Решения по оптимизациям

- Полноразмерный pipeline оставлен: предыдущий Smart Downscaling был
  медленнее на реальных больших JPEG.
- RAM-only image/texture cache оставлен: он нужен для повторного просмотра.
- Prefetch оставлен: он ускоряет переход к следующему изображению, но не
  используется как показатель cold first load.
- WIC протестирован в A/B-режиме, но не принят в production:
  - большой JPEG: WIC 1471 мс против `image` 1367 мс;
  - PNG 3072×1296: WIC 96 мс против `image` 101 мс.
  Небольшой выигрыш на PNG не достигает порога 10%, а JPEG стал медленнее,
  поэтому WIC удалён из основного pipeline.

Результаты зависят от диска, Windows cache, размера изображения и GPU. Для
сравнения вариантов нужно использовать один и тот же компьютер и одинаковые
параметры запуска.
