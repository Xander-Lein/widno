# TDD-цикл

## Чеклист

- [ ] 1. Прочитать утверждённую спецификацию, task graph и критерии приёмки.
- [ ] 2. Проверить текущую ветку или worktree и определить первый вертикальный срез.
- [ ] 3. Если срез независим, назначить субагенту узкую задачу с отдельным контекстом,
  границами файлов и командой проверки.
- [ ] 4. Написать один минимальный тест на публичное поведение из критериев приёмки.
- [ ] 5. Запустить релевантный тест и зафиксировать ожидаемый статус **RED**.
- [ ] 6. Написать минимальную реализацию без speculative features.
- [ ] 7. Запустить тест повторно и получить **GREEN**.
- [ ] 8. Прочитать ошибки при падении, исправить причину и повторить цикл.
- [ ] 9. Повторить шаги 4–8 для следующих вертикальных срезов.
- [ ] 10. Координатор проверяет diff, тесты и контракт результата субагента.
- [ ] 11. Запустить полный набор тестов, линтеры и другие проверки проекта.
- [ ] 12. Сопоставить результаты с каждым критерием приёмки и подготовить отчёт.

## Правила

- Тестируй публичные интерфейсы, а не детали реализации.
- Не подменяй RED искусственным падением: тест должен проверять отсутствующее поведение.
- Не изменяй тест только для получения GREEN без доказательства ошибки в контракте.
- Рефакторинг выполняй после GREEN и снова запускай затронутые проверки.
- При незелёных проверках задача не считается завершённой.
- Не увеличивай число субагентов без необходимости и ограничивай параллелизм.
- Субагент не может объявить задачу GREEN только на основании собственного сообщения;
  координатор запускает или проверяет релевантные команды самостоятельно.
