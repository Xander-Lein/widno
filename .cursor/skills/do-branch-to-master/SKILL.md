# Ветка в master и production

Используй только для явно подтверждённого продвижения изменений. Перед любым commit, push, MR, approve, merge или production pull проверь целевую ветку и запроси подтверждение, если действие не было прямо заказано.

## Чеклист

```
- [ ] 1. Спросить про незакоммиченные изменения
- [ ] 2. Коммиты только того, что пользователь подтвердил
- [ ] 3. Push источника MR
- [ ] 4. MR в `master` + approve + merge
- [ ] 5. git pull 
```

5.
git -C $prod fetch origin --prune
git -C $prod checkout master
git -C $prod pull --ff-only origin master

## Описание шагов

1. Спросить про незакоммиченные изменения, показать их список и не включать неподтверждённые файлы.
2. Сформировать коммиты только из подтверждённых изменений; перед коммитом показать staged diff.
3. Перед push выполнить `/do-documentation`: сверить README, контракты, инструкции,
   ссылки и migration notes с фактическими изменениями. Эту команду также можно
   вызывать отдельно, вне promotion workflow.
4. Отправить исходную ветку в remote и открыть MR с описанием, документацией,
   проверками и границами изменений.
5. Дождаться обязательных проверок, получить approve и выполнить merge в `master` только после подтверждения правил проекта. После merge выполнить release-checklist ниже.
6. В production-каталоге выполнить команды выше с `--ff-only`; при конфликте или расхождении остановиться.

## Release-checklist после merge

- [ ] Подтвердить commit SHA влитого MR и проверить CI.
- [ ] Убедиться, что blocking findings закрыты.
- [ ] Составить release notes: добавлено, изменено, исправлено и затронуто.
- [ ] Определить миграции, ручные действия и обратимый rollback.
- [ ] Проверить правильность production-каталога и ветки.
- [ ] Выполнить production pull только после явного подтверждения.
- [ ] После pull сверить commit и чистоту рабочей директории.
- [ ] Сформировать итоговое сообщение по шаблону ниже.

## Сообщение пользователю

После шага 5 (MR влит и prod pull прошёл) писать в чат **дословно** заголовок и таблицу:

Залито на прод <название ветки>:

| коммиты | добавлено/изменено | требуются действия |
|---------|--------------------|--------------------|
| короткий SHA + subject каждого коммита `origin/master` за этот промоут (через `<br>` в ячейке) | сжатый список смыслов: что появилось или поменялось | конкретные шаги на проде; если ничего — `—` |

Если production pull не прошёл, не используй сообщение об успешной публикации; сообщи точную команду и причину остановки.
