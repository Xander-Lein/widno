# Документация

## Чеклист

- [ ] 1. Определить изменившееся поведение и аудиторию документации.
- [ ] 2. Найти действующие README, API-контракты, инструкции запуска и migration notes.
- [ ] 3. Проверить, какие документы требуют обновления по изменённым файлам и контрактам.
- [ ] 4. Обновить только необходимые разделы: цель, установка, запуск, примеры, ограничения и rollback.
- [ ] 5. Сверить команды, пути, параметры и примеры с фактическим кодом.
- [ ] 6. Проверить локальные ссылки, заголовки, code blocks и отсутствие устаревших утверждений.
- [ ] 7. Запустить доступные документационные проверки и релевантные тесты.
- [ ] 8. Сформировать отчёт с изменёнными файлами, проверками и оставшимися пробелами.

## Правила

- Документация должна описывать фактическое поведение, а не намерения.
- Не выдумывай owner, lineage, гарантии, команды или результаты проверок.
- Если поведение не подтверждено кодом или тестом, укажи это как ограничение.
- Для внешних материалов сохраняй ссылку, авторство и применимые условия лицензии.
