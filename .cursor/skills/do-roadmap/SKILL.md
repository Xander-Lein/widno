# Roadmap проекта

## Чеклист

- [ ] 1. Прочитать README, правила проекта, историю изменений и текущий статус Git.
- [ ] 2. Зафиксировать, что уже сделано, что находится в работе и какие ограничения известны.
- [ ] 3. Найти незавершённые задачи, технический долг, повторяющийся код и места для рефакторинга.
- [ ] 4. Собрать идеи новых фич только из целей проекта, пользовательских потребностей и фактических пробелов.
- [ ] 5. Для каждой инициативы описать ценность, scope, зависимости, риск и критерии готовности.
- [ ] 6. Приоритизировать инициативы по value, urgency, effort и risk; не выдавать длинный список без порядка.
- [ ] 7. Разделить roadmap на `Сделано`, `Сейчас`, `Следом`, `Позже` и `Не делать пока`.
- [ ] 8. Оформить каждый следующий шаг чекбоксом и указать, какая команда запускает работу.
- [ ] 9. Выделить первый небольшой шаг, который можно выполнить без дополнительной декомпозиции.
- [ ] 10. Показать roadmap пользователю и не начинать реализацию без отдельного подтверждения.

## Формат результата

```markdown
# Roadmap

## Сделано
- [x] Результат с доказательством или ссылкой

## Сейчас
- [ ] Инициатива — ценность; зависимости; критерий готовности

## Следом
- [ ] Инициатива — ценность; зависимости; критерий готовности

## Позже
- [ ] Инициатива — причина отложить

## Не делать пока
- Идея — почему сейчас не оправдана

## Следующий шаг
Конкретная задача и команда для запуска.
```

## Правила

- Не считать задачу сделанной только потому, что она есть в README; ищи подтверждение в коде, Git и проверках.
- Не превращать roadmap в бэклог без приоритетов.
- Не добавлять фичи ради количества; каждая идея должна решать явную проблему.
- Для большой инициативы предложить первый вертикальный срез и передать его в `do-plan-and-specs`.
